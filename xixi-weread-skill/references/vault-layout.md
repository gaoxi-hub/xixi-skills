# 笔记库目录规范与硬规则

## 目录结构

笔记库（vault）根目录长这样，`Agent.md` 是它的身份标记：

```
<库根>/
├── Agent.md              目录规范说明，用户维护，以它为准
├── 我的书架.html          微信读书书架同步页（init 生成）
├── 个人笔记/              人写的读书笔记 md，命名「书籍名称-xxx.md」
├── 书籍整理/              每本书的 HTML 整理页，命名「《书籍名称》.html」（read 生成）
└── .weread-cache/        书架与进度缓存，不用手动管
```

`init` 会按这个结构补齐缺失的目录，已存在的一律不动。这一步不需要 API Key、不发网络请求，
永远先做；`我的书架.html` 在这一步生成的是**骨架版**（`synced: false`，没有真实书籍数据），
是否要接着同步真实数据是下一步，交给用户选。

**定位规则**：脚本从当前目录向上找，遇到含 `Agent.md` 或 `书籍整理/` 或 `我的书架.html`
的目录就认作库根。也可以用 `--vault <路径>` 或环境变量 `WEREAD_VAULT` 明确指定。

**如果库根有 `Agent.md`，先读它。** 用户可能改过规范，那份文件优先于本文档。

## 书架页的两条硬规则

用户明确定过、并且返工过的两条。生成完必须复验：

**① 书籍跳转走浏览器，不走 App 协议。**
卡片上的书籍入口用 `/shelf/sync` 返回的 `deepLink`（`https://weread.qq.com/...`），
不要用 `weread://reading?bId=...`。断言方式：渲染后的 DOM 里 `href="weread://"` 出现次数为 0。

（书籍**页内部**的划线/章节深链用 `weread://` 是对的，那是书内定位，不受这条限制。）

**② 卡片上的「📝 笔记」跳本地整理页。**
指向 `书籍整理/《书名》.html`，靠扫目录 + 书名精确匹配回填 `noteUrl`。

由 ② 推出一条操作纪律：**每次新增或改名书籍整理页之后，必须重新生成 `我的书架.html`**，
否则新页面的笔记入口挂不上。`build_book.py` 结尾已经自动做了这一步，
但如果你手动重命名了 `书籍整理/` 下的文件，要自己补一次：

```bash
python3 $SK/init_shelf.py --no-refresh
```

（`$SK` 是这个 skill 的 `scripts/` 目录，见 SKILL.md 顶部说明——不同安装方式路径不同，
别把 Kiro 的默认路径 `~/.kiro/skills/xixi-weread-skill/scripts` 当成唯一路径。）

`--no-refresh` 只重渲染、不重新拉接口，几秒就好。

## 书名匹配的两处约定

**书架卡片 → 整理页**：把文件名 `《X》.html` 剥掉书名号后与书架条目的 `title` **精确**比较。
所以整理页文件名里的书名必须和微信读书里的书名完全一致（副标题、括号、全半角都算），
否则笔记入口静默挂不上 —— 这是最容易踩的一处，因为不报错。

**整理页 → 个人笔记 md**：用书名前缀在 `个人笔记/` 下模糊找（先整名，再退到前 6 字、前 4 字）。
宽松是故意的，因为 md 命名规范是「书籍名称-xxx.md」，后缀由人自由发挥。
找不到就把整理页的个人笔记板块留空，不算失败。

## 个人笔记 md 支持的写法

`build_book.py` 里的 `render_md` 是一个刻意做窄的 markdown 子集。不引通用渲染器是因为
这台机器的系统 python 是 externally-managed，`pip install markdown` 会失败，
引依赖就得连带拖一个 venv 出来 —— 对一个生成静态页的 skill 来说太重了。

| 写法 | 变成 |
|------|------|
| `# 标题` / `## 标题` | `<h3>` |
| `### 标题` 及更深 | `<h4>`（模板里板块标题已占用 h2） |
| 顶格 `1. **短语**`（整行只有这个加粗短语） | `<h4>短语</h4>` |
| 顶格 `1. **短语**：后面还有内容` | `<ol><li><strong>短语</strong>：…</li></ol>` |
| 缩进的 `1. 文本` | `<ol><li>文本</li></ol>` |
| `- 文本` / `* 文本` | `<ul><li>文本</li></ul>` |
| `\| a \| b \|` + `\|---\|---\|` 分隔行 | `<table>` |
| ` ```markdown ` 围栏 | `<details>` 折叠块，内层递归当 markdown 渲染 |
| ` ```python ` 等真实语言围栏 | `<pre><code>` |
| `**加粗**` / `` `代码` `` | `<strong>` / `<code>`（行内，任意位置生效） |
| 其他非空行 | `<p>文本</p>` |

`&` `<` `>` 会被转义，笔记里写 HTML 不会破页也不会生效。

两条值得知道理由的设计：

**为什么围栏默认折叠而不是当代码。** 这个库里的 ` ```markdown ` 装的是「展开解释」——
成段的说明文字、嵌套列表、表格。按代码块渲染会糊成一大坨等宽字没法读，
所以按语言标记分流：真实编程语言走 `<pre><code>`，其余当可折叠的补充说明。

**为什么加粗小标题要求「整行只有加粗」。** 早先的判据是「这行含 `**`」，于是
`1. **本质**：主动求己、尊重规律、借势而起，而非单靠蛮力或短期技巧。` 整句被塞进 `<h4>`，
一个句子当标题很怪。现在只有 `1. **全书结构与定位**` 这种纯短语才升级成小标题。

图片、链接、引用块、嵌套列表层级还不支持，会退化成普通段落或平铺列表。
要加语法就在 `render_md` 里补分支，**同时在这张表里补一行** —— 否则下一个人会以为不支持而绕路。
改完记得按 SKILL.md 的无头 Chrome 断言复验：新语法要是没有对应 CSS，页面会渲染成没样式的裸元素
（`assets/book_template.html` 里 `.notes` 那一段就是笔记正文的样式）。
